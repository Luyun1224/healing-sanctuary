## 重要說明

以下測試在**本機 GAS 模擬器**（`tools/gas-emulator.mjs`）上執行：它在 Node 中執行與正式環境相同的 `gas/Code.gs`，
但 SpreadsheetApp、CacheService、LockService、PropertiesService 是記憶體模擬。因此：

- **已驗證**：前後端協定、資料驗證、token 權限、節流、離線清除、快取遺失復原、前端插值與 UI 行為。
- **尚未驗證**：Google 實際的回應時間、配額、同時執行上限、CacheService 實際淘汰行為、302 轉址後的 CORS 讀取。
  這些必須在部署後以 `tools/load-test.mjs --url <正式網址>` 實測（步驟見 [GAS-SETUP.md](GAS-SETUP.md)）。

### 快取遺失壓力測試的發現與修正

第一次以「每次讀取 2% 機率遺失」的極端設定測試時，共用的房間索引被清除會讓所有人短暫看不到彼此（成功率 79.6%，主要為 `expired` 後自動重新加入）。
已改為在 PropertiesService 保存房間索引備份（只在名單變動時寫入），並把模擬器改為較接近實際的「每項每分鐘遺失機率」。

| 人數 | 請求數 | 每秒請求 | 成功率 | 錯誤 | 回應 p50 / p95 / max | 看到的在線人數 |

在線人數最小值較低是因為模擬玩家在開始的 3 秒內陸續加入、結束時陸續離開。

### 解讀與限制

- **25 人可以同時在線**：所有模擬玩家都成功加入並互相看見（最高 25 人）。
- `busy` 發生在多人幾乎同時加入、搶房間名單鎖的時候；前端收到 `busy` 會在 3 秒後自動重試，使用者只會感覺加入稍慢。
- Apps Script 回應時間中位數約 1 秒，p95 約 2～5 秒、最慢 9 秒。加上 6～10 秒的輪詢間隔，**其他人的位置大約延遲 6～15 秒**，符合「不保證即時」的設計預期；畫面上以平滑移動補間。
- 這是 GitHub Actions 機房的測試結果；院內網路、實際瀏覽器與尖峰時段的表現仍建議找同事實際上線確認。
